## 模块 ① 数据清洗 · data_clean.py

**职责**：把脏的原始信令数据，按 **9 条规则**变成 6 列标准表。

**输入**：`data/raw/原始数据.csv`（~53 万行，UTF-8，无表头，10 列）、`data/raw/基站经纬度数据.csv`
**输出**：`result/cleaned_data.csv`（固定 6 列：`imsi, time, lac_id, cell_id, lon, lat`）
**入口**：`main()`

### 9 条规则（[data_clean.py#L78-L155](file:///workspace/project_code/data_clean.py#L78-L155)）

| # | 规则 | 实现要点 |
| --- | --- | --- |
| 1 | 字段抽取 | 只读前 4 列（time/imsi/lac_id/cell_id），`dtype=str` 防丢前导零 |
| 2 | 去脏 imsi | 正则 `[#* ^\s]` 删除含 `#`、`*`、空格、空白符的 imsi |
| 3 | 去空 | 删 `lac_id` / `cell_id` 缺失或空串的行 |
| 4 | 时间转换 | 13 位毫秒 UTC 时间戳 → +8h 北京时间 → `YYYYMMDDHHMMSS` 字符串；非毫秒格式走 `pd.to_datetime` 兜底 |
| 5 | 目标日过滤 | 只保留 `time` 以 `20181003` 开头的行（`TARGET_DATE`） |
| （额外）| 教学抽样 | `sample_by_user()`：**整用户**抽样约 2 万行；`SAMPLE_ROWS=0` 时全量 |
| 6 | 基站关联 | 拼 `laci = lac_id-cell_id`，左连接基站表补 lon/lat，删除未匹配行 |
| 7 | 排序 | 按 `imsi + time` 排序（阶段1 `shift(1)` 找"上一条"的前提） |
| 8 | 分钟去重 | 同一 `imsi` 同一分钟（`time[:12]`）只留第一条 |
| 9 | 稀疏用户过滤 | 当天点数 < `MIN_POINTS_PER_USER`(20) 的用户整用户删除 |

### 关键点

- **整用户抽样**（`sample_by_user`）：以"用户"为单位抽样，选中即保留完整轨迹，避免轨迹被抽碎导致规则9 几乎删光。`eligible.sample(frac=1.0, random_state=42)` 保证可复现。
- **每步留痕**：`_step(name, before, after)` 打印每步行数变化，出问题即刻定位。
- **列顺序固定**：最终 `df = df[['imsi','time','lac_id','cell_id','lon','lat']]`，下游强依赖。

## 模块 ② 出行 & 驻留识别 · tr_stage1 / tr_stage2 / tr_stage3

模块②是三阶段流水线，逐层从"全部点"收敛到"每个点的出行/驻留标签"。

### ②-1 阶段1 · 预处理（速度粗筛）· tr_stage1.py

**职责**：把标准表整理成按用户/时间排序的轨迹点表，用速度粗筛出疑似出行点。
**输入**：`result/cleaned_data.csv`
**输出**：`data/processed/stage1_dt.csv`（列：`imsi, time, lac_id, cell_id, lon, lat, speed`）
**入口**：`main()`

**核心步骤**（[tr_stage1.py#L38-L76](file:///workspace/project_code/tr_stage1.py#L38-L76)）：

1. 读标准表（ID 列 `dtype=str`）；`time_dt = parse_time(time)`。
2. **低频点过滤**：按 `(imsi, lon, lat)` 计数，出现 <4 次的位置点剔除。
3. **切段 `seg_id`**：用户变化或位置变化即开启新段（`groupby(imsi).cumsum()`）。
4. **计算速度**：
   - `time_diff = groupby(imsi).time_dt.diff()`（秒）
   - `prev_lon/prev_lat = groupby(imsi).shift(1)`
   - `dist_km = Harversine(prev_lon, prev_lat, lon, lat)`
   - `speed = dist_km * 3600 / time_diff`（km/h，保留 2 位）
   - 异常速度（`<0` 或 `> ABNORMAL_SPEED`）置 `NaN`（**不删行**）
5. **粗筛出行点**：`is_travel = speed > SPEED_THRESHOLD(8)`。
6. 只保留出行点 + `speed`，写 `stage1_dt.csv`。

**字段契约** `TRAJECTORY_COLS`（[tr_stage1.py#L32-L35](file:///workspace/project_code/tr_stage1.py#L32-L35)）：
`imsi, time, lac_id, cell_id, lon, lat, time_diff, dist_km, speed, seg_id, is_travel`

> 注：实际写出的 `stage1_dt.csv` 只含其中 7 列（`imsi,time,lac_id,cell_id,lon,lat,speed`），`time_diff/dist_km/seg_id/is_travel` 是中间计算列，未落盘。

### ②-2 阶段2 · 聚类（手写 k-means + 选 k）· tr_stage2.py

**职责**：对阶段1 的出行点**逐用户**聚类，找出驻留候选点。
**输入**：`data/processed/stage1_dt.csv`
**输出**：`data/processed/stage2_cluster.csv`（阶段1 出行点 + `cluster` + `is_single_cluster`）
**入口**：`main(seed=42)`

**核心算法**：

| 函数 | 作用 |
| --- | --- |
| [`pairwise_euclidean(X)`](file:///workspace/project_code/tr_stage2.py#L41-L60) | 广播一次算出 (n,n) 欧氏距离矩阵，各候选 k 复用 |
| [`kmeans(X, k)`](file:///workspace/project_code/tr_stage2.py#L63-L106) | 手写 k-means：随机初始化 → 分配步 → 更新步 → 收敛判断；空簇保留旧中心避免 NaN |
| [`silhouette_score(D, labels)`](file:///workspace/project_code/tr_stage2.py#L109-L141) | 轮廓系数：Σ(b−a)/max(a,b) 的均值，范围 −1~1 |
| [`dunn_index(D, labels)`](file:///workspace/project_code/tr_stage2.py#L144-L170) | 邓恩指数：簇间最小距离 / 簇内最大直径，越大越好 |
| [`choose_best_k(X)`](file:///workspace/project_code/tr_stage2.py#L173-L197) | k 从 `K_MIN=2` 到 `K_MAX=10` 试跑，打分 `轮廓系数 + 0.1×邓恩指数` 选最优 |

**主流程**（[tr_stage2.py#L200-L261](file:///workspace/project_code/tr_stage2.py#L200-L261)）：

1. 读阶段1 结果（文件不存在/为空 → 抛 `FileNotFoundError`，提示先跑阶段1）。
2. `np.random.seed(seed)` 固定随机源。
3. `groupby('imsi', sort=False)` 逐用户聚类 → `choose_best_k` → 写 `cluster`。
4. `is_single_cluster`：簇内只有 1 个点记 1（供阶段3 直接判出行）。
5. 拼表落盘，并返回统计字典（输入行数、用户数、簇数、单点簇数、输出路径）。

**打分公式**：`score = silhouette_score(D, labels) + 0.1 * dunn_index(D, labels)`——轮廓系数为主、邓恩指数小权重辅助（两者量级不同，用 0.1 平衡）。

### ②-3 阶段3 · 业务判定 · tr_stage3.py

**职责**：在聚类结果上按业务规则判定每个簇是"驻留"还是"出行"。
**输入**：`data/processed/stage2_cluster.csv` + `result/cleaned_data.csv`
**输出**：`result/stage3_label.csv`（列：`imsi, time, lac_id, cell_id, lon, lat, label`）
**入口**：`main()`

**判定规则**（[tr_stage3.py#L30-L81](file:///workspace/project_code/tr_stage3.py#L30-L81)）：

| 情况 | 判定 |
| --- | --- |
| `is_single_cluster==1` 或簇内只有 1 个点 | **出行**（label=1） |
| 多点簇：首/中/尾三点到簇中心距离均 `< CLUSTER_DIST_THRESHOLD`(1000m) **且** 首末时间跨度 `< TIME_SPAN_THRESHOLD`(2h) | **驻留**（label=0） |
| 多点簇：不满足上述条件 | **出行**（label=1） |
| 未进入任何簇（左连接产生 `NaN`，`cluster=-1`） | 保持默认 **驻留**（label=0） |

**实现要点**：

- 先把 `cluster` 结果左连接到清洗表（`on=['imsi','time']`），`assert len(df)==len(cleaned)` 防重复键。
- `cluster` 缺省填 −1、`is_single_cluster` 缺省填 0。
- `label` 初始化为 0，再对进入簇的点逐个判定覆盖。
- 距离用 `Harversine(center, point, unit='m')`（真实球面距离）；时间跨度用 `time_dt` 差。

## 模块 ③ 出行目的识别 · purpose.py

**职责**：判定每次驻留的目的——**居住 / 购物 / 旅游 / 其他**。
**输入**：`result/stage3_label.csv`、`data/raw/出行目的静态数据.csv`（GBK，列序 lon,lat,目的,目的地）
**输出**：`result/purpose_result.csv`（每驻留段一行）
**入口**：`main()`

**主流程**（[purpose.py#L57-L169](file:///workspace/project_code/purpose.py#L57-L169)）：

1. **读标签表**并按 `imsi+time` 排序。
2. **驻留段识别**：`is_stay = (label==0)`；按"用户变化或停留状态变化"切 `seg_id`；`groupby(imsi, seg_id)` 聚合出每段 `start_time/end_time/points/center_lon/center_lat`，并算出 `duration_hours/start_hour/end_hour`。
3. **时间规则粗判** `judge_purpose_by_time(start_hour, end_hour, duration_hours)`：
   - 居住：`duration > 4h` 且 开始/结束时段在夜间（0–6 或 20–23）。
   - **先窄后宽**：旅游（9–17）是购物（9–21）的子集，必须先判旅游再判购物，否则 9–17 段被购物吞掉。
   - 兜底：都不满足 → 其他。
4. **读 POI 静态数据**：显式按文件真实字段顺序命名 `["lon","lat","poi_type","poi_name"]`（**列序不能想当然**，写错会把 1273 行全删光）。
5. **POI 空间匹配**：每个驻留段中心点到全部 POI 算 `Harversine`，最近距离 `< MATCH_THRESHOLD(1000m)` 判匹配成功，记录 `nearest_poi_name/type/dist_m`。
6. **最终目的融合**：`final_purpose` 先用时间规则打底，匹配成功的段用最近 POI 的 `poi_type` 覆盖（**POI 优先**，时间规则兜底）。
7. `save_result(segments, RESULT_FILES['purpose'])`。

**关键函数**：`judge_purpose_by_time`（时间规则）、局部 `haversine`（
注：模块内另有一份 `haversine`，与 `utils.Harversine` 并存，实际匹配用的是 `Harversine`）。

## 模块 ④ 出行方式识别 · mode.py

**职责**：判定每次出行采用的方式——**地铁 / 公交 / 小汽车 / 其他**。
**输入**：`result/stage3_label.csv`、`data/raw/出行方式静态数据.csv`（GBK，5 列：经度,纬度,方式类型,站点名,线路名）
**输出**：`result/mode_result.csv`（每出行段一行）
**入口**：`main()`

**主流程**（[mode.py#L65-L170](file:///workspace/project_code/mode.py#L65-L170)）：

1. 读标签表并排序；`is_travel = (label==1)`；按用户/出行状态变化切 `seg_id`。
2. **聚合出行段**：`groupby(imsi, seg_id)` 得 `start/end_time, point_count, 起终点坐标`；过滤 `point_count >= 2`。
3. **平均速度**：逐段内相邻点算 `haversine 距离 / 时间差`，剔除 0 与 >200 的异常值后取均值，写入 `avg_speed`。
4. **速度粗判** `judge_mode_by_speed(avg_speed)`：<12 其他 / 12–20 公交档 / >20 地铁或小汽车档（存 `mode_speed`，仅供参考）。
5. **读站点静态数据**：命名 `["lon","lat","mode_type","station_name","line_name"]`；清洗后按 `mode_type` 含"地铁"/"公交"拆成两组。
6. **站点匹配**：每个出行段内**逐轨迹点**判断 500m 内是否压过地铁站/公交站，统计命中点数 `subway_hit_count` / `bus_hit_count`。
7. **最终判定** `final_mode_judge(subway_cnt, bus_cnt, avg_speed)`：

   | 条件（按优先级） | 结果 |
   | --- | --- |
   | 命中 ≥2 个地铁站 | 地铁 |
   | 命中 ≥3 个公交站 | 公交 |
   | 都没命中且 `avg_speed > 20` | 小汽车 |
   | 其余 | 其他 |

8. 输出 14 列结果：`imsi, seg_id, start_time, end_time, point_count, lon_start, lat_start, lon_end, lat_end, avg_speed, mode_speed, subway_hit_count, bus_hit_count, final_mode`。

**设计要点**：地铁站间距大、误命中少，阈值低（2）；公交站密、易误命中，阈值高（3）。地铁与小汽车速度接近，靠站点匹配才能区分。

## 模块 ⑤ 实时商圈热力 · heatmap.py

**职责**：统计**每个商圈在过去 10 分钟**的人次（滑窗）。
**输入**：`data/raw/实时流数据.csv`（time,imsi,lon,lat）、`data/raw/商业区数据.csv`（lon,lat,biz_name）
**输出**：`result/heatmap_result.csv`（列：`minute, biz_name, count, hour`）
**入口**：`heatmap_analysis()`

**主流程**（[heatmap.py#L12-L81](file:///workspace/project_code/heatmap.py#L12-L81)）：

1. 读实时流，数值化 lon/lat，只保留目标日 `20181003`，解析 `time_dt`。
2. 读商圈数据并清洗。
3. **分批广播距离匹配**（`BATCH_SIZE=10000`）：每批点与全部商圈算 `Harversine(unit='m')`，取最近商圈；最近距离 `< HEATMAP_MATCH_THRESHOLD(1000m)` 才算命中，回填 `biz_name`。
4. 计算当日分钟序号 `min_of_day = hour*60 + minute`（0~1439）。
5. `groupby(['min_of_day','biz_name']).size().unstack()` 得"分钟 × 商圈"面板，`reindex` 补齐 0~1439 分钟。
6. **10 分钟滚动窗口求和**：`panel.rolling(WINDOW_MINUTES, min_periods=1).sum()`。
7. `stack` 还原成长表，命名 `minute, biz_name, count`，加 `hour = minute // 60`，过滤 `count>0`。
8. `save_result` 落盘供模块⑥画热力图。

**设计要点**：分批广播避免一次性构造超大 (n点 × m商圈) 矩阵，控制内存。

## 展示层 · Dashboard.py（Streamlit 大屏）

**职责**：将全局指标 + 6 张图汇成一屏。
**输入**：`result/stage3_label.csv` + `result/figures/*.png`
**运行**：`streamlit run project_code/Dashboard.py`

**结构**：

1. 页面基础配置：`st.set_page_config(layout="wide")`。
2. **顶部 KPI 指标栏**：总轨迹样本、驻留样本数、出行样本数、驻留/出行比例（从 `stage3_label.csv` 现算）。
3. **2 行 3 列图表布局**：依次内嵌 6 张 PNG。
4. 底部项目说明 markdown（label 语义、热力图、3D 轨迹含义）。

> ⚠️ 注意：Dashboard 用硬编码图片名（`fig_stage3_pie.png` 等）读取，因此**必须先运行模块⑥生成全部 6 张图**，否则对应位置报图缺失。

## 编排层 · main.py

**职责**：一键串联 8 个入口 + 结果核对。
**入口**：`main()`

- `run_modules()`：顺序执行 `MODULES` 列表，`with Timer(name)` 计每模块耗时；单模块异常只 `log` + `traceback.print_exc()`，继续后续。
- `check_results()`：核对 `RESULT_CSVS`(7) + `RESULT_FIGS`(6) 是否存在并打印大小/`[缺失]`。
- `main()`：跑全流程 + 打印最终齐全与否。
