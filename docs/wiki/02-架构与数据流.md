# 02 · 架构与数据流

## 2.1 分层架构

项目采用"**配置层 → 工具层 → 业务模块层 → 编排层 → 展示层**"的简单分层，各层单向依赖：

```
┌───────────────────────────────────────────────────────────┐
│  展示层        Dashboard.py (Streamlit 大屏)                │
├───────────────────────────────────────────────────────────┤
│  编排层        main.py  (顺序执行 + 单模块容错 + 结果核对)     │
├───────────────────────────────────────────────────────────┤
│  业务模块层                                                  │
│   ①data_clean  ②tr_stage1/2/3  ③purpose  ④mode               │
│   ⑤heatmap     ⑥visualize                                    │
├───────────────────────────────────────────────────────────┤
│  工具层        utils.py (读/写/距离/绘图/日志/计时)           │
├───────────────────────────────────────────────────────────┤
│  配置层        config.py (路径 + 阈值 + 文件名)               │
└───────────────────────────────────────────────────────────┘
```

**关键约束**：

- 业务模块**只**从 `config` 取路径/参数、从 `utils` 取公共函数，不互相 import（保持模块独立可单跑）。
- `main.py` 是唯一的编排者，它 import 各业务模块并按数据流顺序调用其 `main()` 入口。
- `Dashboard.py` 依赖 `config` + `utils` 读取结果表，并读取 `result/figures/` 下的图片。

## 2.4 三阶段识别流水线（模块②核心设计）

模块②是整个系统的算法核心，拆成三阶段、逐层收敛：

```
清洗后的标准表 (全部点)
      │  阶段1：速度粗筛
      ▼
【stage1_dt.csv】只保留"疑似出行"的点 (speed > 8 km/h)
  - groupby(imsi).shift(1) 找同用户上一条
  - Haversine 算相邻点距离 → speed
  - >200 km/h 判为基站跳跃假高速 → speed 置空(不删行)
      │  阶段2：聚类找驻留候选
      ▼
【stage2_cluster.csv】出行点上加 cluster / is_single_cluster
  - 逐用户聚类，k 从 2~10 试，轮廓系数 + 0.1×邓恩指数打分选最优 k
  - 手写 k-means（平面欧氏近似）
      │  阶段3：业务规则精判
      ▼
【stage3_label.csv】对每个点打 label（0=驻留 / 1=出行）
  - 单点簇 → 直接判出行
  - 多点簇：首/中/尾三点到簇中心 <1km 且首末时间跨度 <2h → 驻留，否则出行
  - 未进入任何簇的点(左连接 NaN) → 归为驻留
```

这三阶段的"分工约定"：**聚类用平面近似、判阈值用真实距离**——阶段2 用欧氏距离加速聚类，阶段3 的 1km 阈值判定使用 Haversine 真实球面距离。

## 2.5 关键架构设计点

### 2.5.1 路径锚定，与运行目录无关

每个可执行脚本开头都插入项目根目录到 `sys.path`，所有路径由 `config.PROJECT_ROOT`（基于 `__file__` 锚定）推导，因此**从任意目录运行均可**：

```python
sys.path.insert(0, str(Path(__file__).resolve().parent.parent))
```

### 2.5.2 单模块容错 + 结果核对（main.py）

[main.py](file:///workspace/project_code/main.py) 按数据流顺序串联 8 个入口，单模块失败**只打印 traceback 并继续**；跑完自动核对 7 CSV + 6 PNG 产出情况（缺失标 `[缺失]`）。这保证一次全量运行能尽量多地产出结果，并能定位到具体缺哪一步。

```python
MODULES = [
    ("① 数据清洗", data_clean.main),
    ("②-1 阶段1 速度粗筛", tr_stage1.main),
    ("②-2 阶段2 KMeans聚类", tr_stage2.main),
    ("②-3 阶段3 规则精判", tr_stage3.main),
    ("③ 出行目的识别", purpose.main),
    ("④ 出行方式识别", mode.main),
    ("⑤ 实时热力分析", heatmap.heatmap_analysis),
    ("⑥ 可视化", visualize.visualize_all),
]
```

见 [main.py#L36-L45](file:///workspace/project_code/main.py#L36-L45)。

### 2.5.3 可复现性

- 数据清洗整用户抽样固定 `random_state=42`。
- 阶段2 聚类在 `main(seed=42)` 中先 `np.random.seed(seed)`，且 `groupby(..., sort=False)` 保持输入顺序，输出字节级可复现。
- 阶段2 选 k 时"分数打平保留更小的 k"（严格大于才替换）。

### 2.5.4 编码与 ID 类型兜底

原始数据编码不统一：`出行目的静态数据.csv` / `出行方式静态数据.csv` 为 **GBK**，其余为 UTF-8。`utils._read_csv_any_encoding` 先试 UTF-8、失败回退 GBK。同时 `imsi` / `lac_id` / `cell_id` 一律按字符串读写，防止丢前导零、避免与基站表拼 `laci` 时匹配率归零。
